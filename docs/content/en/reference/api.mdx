`Disintegrator` ties together one complete visual configuration, optional audio, capture, layout animation, background preparation, and retained-node storage.

The root and `/snapdom` entries register four complete built-in presets; only `/snapdom` supplies a capture adapter. `/core` provides the lifecycle without built-in presets, particles, sounds, or capture. No entry chooses a default preset.

## Constructor

```ts
import Disintegrator from 'vanilla-disintegrate/snapdom';

const ready = new Disintegrator({ preset: 'dust' });
const custom = new Disintegrator({ effect: fade });
```

Exactly one of `preset` and `effect` is required:

```ts
type DisintegratorOptions =
  | { preset: PresetSelection; effect?: never; sound?: false }
  | { preset?: never; effect: EffectDefinition; sound?: false | SoundSelection };
```

A preset is an atomic visual-and-audio choice. It may be muted with `sound: false`, but it cannot be combined with replacement visuals or audio. A custom effect is an object with complete `remove` and `restore` phases; it is silent unless a sound pair is supplied.

Shared options:

| Option                 | Type                                                        | Default         | What it does                                                       |
| ---------------------- | ----------------------------------------------------------- | --------------- | ------------------------------------------------------------------ |
| `presets`              | `Record<string, PresetDefinition>`                          | `{}`            | Adds complete custom presets addressable through `preset`          |
| `layout`               | `boolean \| LayoutOptions`                                  | `true`          | Moves neighbours into their new places after removal               |
| `preparation`          | `boolean \| PreparationOptions`                             | `visible-idle`  | Prepares snapshots for registered elements                         |
| `audioPreparation`     | `false \| 'immediate' \| 'idle' \| AudioPreparationOptions` | `'idle'`        | Controls preparation and the decoded-audio ownership budget        |
| `respectReducedMotion` | `boolean`                                                   | `true`          | Skips animation when the user requests less motion                 |
| `capture`              | `SnapshotCapture`                                           | SnapDOM¹        | Turns an element into a canvas for snapshot-based effects          |
| `overlayRoot`          | `HTMLElement \| () => HTMLElement`                          | `document.body` | Receives fixed-position animation overlays                         |
| `zIndex`               | `number`                                                    | `2147483646`    | Sets the overlay stack level                                       |
| `random`               | `() => number`                                              | `Math.random`   | Seeds one repeatable pseudo-random stream per operation            |
| `snapdom`              | `SnapdomOptions`                                            | —               | Configures SnapDOM's `toCanvas()`; available only from `/snapdom`  |
| `onTrigger`            | `(context) => void`                                         | —               | Runs after validation and before capture                           |
| `onStart`              | `(context) => void`                                         | —               | Runs after the DOM change as playback begins                       |
| `onComplete`           | `(context) => void`                                         | —               | Runs after a visual phase completes normally                       |
| `onError`              | `(error, context) => void`                                  | —               | Receives isolated capture, animation, sound, and callback failures |

¹ SnapDOM is the default only for `/snapdom`. The root and `/core` entries require `capture` when the chosen effect needs a snapshot.

Background snapshot failures report `context.operation === 'prepare'`; operation failures report `remove` or `restore`.

## Complete presets

```ts
import { definePreset } from 'vanilla-disintegrate';

const dissolve = definePreset({
  effect: fade,
  sound: {
    remove: { src: '/audio/out.ogg', volume: 0.4 },
    restore: { src: '/audio/in.ogg', volume: 0.4 },
  },
});

const effects = new Disintegrator({
  preset: 'dissolve',
  presets: { dissolve },
});
```

`definePreset()` freezes the preset, visual phases, and native sound option objects without freezing caller-owned binary audio data.

## remove(target, options?)

Detaches the resolved element and returns `EffectOperation` synchronously.

```ts
const operation = effects.remove('.card', {
  preset: 'scatter',
  sound: false,
  retain: true,
  layout: { duration: 260 },
  detach: (element) => element.remove(),
});
```

`target` may be an `HTMLElement` or selector string. A missing selector throws before an operation starts.

`detach` replaces the default `element.remove()` commit. Use it when a reactive renderer must remove the node through its own state. If it throws, the error is sent to `onError` and native removal is used as a safe fallback.

## restore(target, options?)

Animates a connected, measurable element in its current geometry.

```ts
const operation = effects.restore(element, {
  preset: 'scatter',
  sound: false,
});
```

The method throws when the element is detached or has zero width or height.

For either operation, pass one complete `preset`, one custom `effect` with an optional sound definition for that phase, or neither to inherit the instance or retained-node presentation. Inherited or preset audio may only be muted with `sound: false`.

## Retained elements

```ts
const element = effects.take(removalId); // HTMLElement | null
const discarded = effects.discard(removalId); // boolean
const count = effects.discardAll(); // number
```

`take()` consumes the stored entry. `discard()` and `discardAll()` release references without inserting content.

## Snapshot preparation

```ts
const unregister = effects.register(elements);
await effects.prepare(elements);
effects.invalidate(elements);
effects.clearPrepared();
```

`register()` follows the configured strategy. `prepare()` captures immediately even when background preparation is disabled. Repeated registrations of the same element are reference-counted; every returned unregister function releases only its own registration.

## Audio preparation

```ts
await effects.prepareAudio({
  remove: { src: 'dust' },
  restore: { src: 'dust', reverse: true },
});
effects.discardPreparedAudio();
effects.clearPreparedAudio();
```

Without an argument, `prepareAudio()` and `discardPreparedAudio()` use the instance's configured sound pair. Explicit methods work even when automatic preparation is disabled. Decoded buffers use a bounded per-instance ownership LRU while fetches, buffers, and `AudioContext` are shared across instances.

## destroy()

```ts
effects.destroy();
```

Cancels active operations, stops observers and background work, releases snapshot and decoded-audio ownership, and clears retained nodes. The shared playback context closes when its last owner is destroyed. Calling `destroy()` more than once is safe; starting new work afterwards throws.

## EffectOperation

```ts
interface EffectOperation {
  readonly operation: 'remove' | 'restore';
  readonly removalId: RemovalId | null;
  readonly finished: Promise<{
    operation: 'remove' | 'restore';
    status: 'completed' | 'cancelled' | 'skipped' | 'rejected';
    removalId: RemovalId | null;
  }>;
  cancel(): void;
}
```

The handle does not expose the element and drops its reference after settlement.

| Status      | Content action                                | When `finished` resolves     |
| ----------- | --------------------------------------------- | ---------------------------- |
| `completed` | Committed; the visual phase finished normally | After visual cleanup         |
| `cancelled` | Committed; visual or audio playback stopped   | After cancellation cleanup   |
| `skipped`   | Committed without a runnable visual phase     | After fallback cleanup       |
| `rejected`  | Not started; the DOM was not changed          | After the current owner ends |

## Callbacks and precedence

Instance callbacks run for every operation; operation callbacks run alongside them. Explicit operation presentation wins, then a retained node's remembered presentation, then the instance configuration. A concurrent call for an element already in use resolves as `rejected` after the current owner settles.
