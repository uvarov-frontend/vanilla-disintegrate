声音默认关闭：传入 `sound: true` 启用内置音频。请从点击等用户手势中调用 `remove()` 或 `restore()`，让库能够恢复 Web Audio 播放。每个删除与恢复阶段都有独立声音定义，因此恢复音轨无需倒放删除音轨。

## 开启与关闭声音

```ts
const audible = new Disintegrator({ sound: true });
const silent = new Disintegrator();
effects.remove(element, { sound: true });
```

操作级选项只覆盖当前调用。

## 在首次交互前准备

实例设置 `sound: true` 后，默认选中的效果会立即获取并解码。只准备该效果：`effect: 'vapor'` 不会加载另外三个内置文件。若首屏渲染比首次交互就绪更重要，可使用 `idle`：

```ts
const effects = new Disintegrator({
  effect: 'vapor',
  sound: true,
  audioPreparation: 'idle',
});
```

如果界面可选择多个效果，请准确列出这些效果，或显式准备：

```ts
const effects = new Disintegrator({
  sound: true,
  audioPreparation: {
    strategy: 'immediate',
    effects: ['dust', 'scatter', 'vapor', 'wind'],
  },
});

await effects.prepareAudio(['dust', 'wind']);
effects.discardPreparedAudio('dust');
effects.clearPreparedAudio();
```

`audioPreparation: false` 会禁用自动准备。`prepareAudio()` 是显式操作，因此即使实例声音关闭也能工作。若某次操作选择了尚未准备的原生声音，视觉与音频会等待解码完成后同步开始，内置声音不会在动画进行中途加入。自定义播放器工厂自行负责加载，不会在准备阶段被调用。

正向与反向解码缓冲区默认共享 8 MiB 的 LRU 预算。同一页面上的实例会复用一次获取、解码缓冲区和 `AudioContext`，但各自管理播放。可通过 `audioPreparation.cacheByteBudget` 调整预算；`destroy()` 会释放该实例的所有权，最后一个所有者会关闭共享上下文。

## 声音放在哪里

声音写在效果里，每个阶段一个：

```ts
const snap = '/sounds/snap.mp3';

const fold = defineEffect({
  remove: { animate: out, sound: { src: snap } },
  restore: { animate: back, sound: { src: snap, reverse: true } },
});
```

实例上和调用上的 `sound` 只是它们的开关：

```ts
const effects = new Disintegrator({ effect: fold, sound: true });

effects.remove(card); // 播放效果里的声音
effects.remove(card, { sound: false }); // 静音，动画不变
```

有一点要注意。如果在那里传的不是 `true` 或 `false` 而是一个声音，它不会起开关作用——它会替换效果里的声音，两个阶段用同一个文件：

```ts
new Disintegrator({ sound: { src: '/sounds/snap.mp3' } });
// 删除和恢复都会正向播放 snap.mp3
```

只用一个声音时这样很方便。想让删除和恢复各有各的声音，就写进效果里。

## 为删除与恢复配对

| 需求                 | `remove`        | `restore`                      |
| -------------------- | --------------- | ------------------------------ |
| 一个文件，恢复时倒放 | `{ src: snap }` | `{ src: snap, reverse: true }` |
| 两个不同的文件       | `{ src: out }`  | `{ src: back }`                |
| 只在删除时发声       | `{ src: snap }` | `null`                         |

四个内置效果都使用第一行。

## 支持的来源

```ts
type SoundSource = string | URL | ArrayBuffer | AudioBuffer;
```

字符串与 `URL` 会在自动、显式或按需准备时获取并解码；应用自己加载资源时可传 `ArrayBuffer`；已有音频资源管线时可复用 `AudioBuffer`。

库不会把压缩音频文件强制转换并打包成 `AudioBuffer`：解码是浏览器运行时工作，而压缩文件更小且可缓存。

## 播放参数

```ts
const sound = {
  src: new URL('/sounds/snap.ogg', location.href),
  gain: 0.35,
  delay: 40,
  duration: 0.7,
  fadeDuration: 0.12,
  playbackRate: 1.05,
};

effects.remove(element, { sound });
```

## 倒着播放

恢复动画是独立的，但它的声音可以倒放删除录音。这样一个文件就够用，不必再录一份：

```ts
const remove = { src: '/sounds/snap.mp3' };
const restore = { src: '/sounds/snap.mp3', reverse: true };
```

四个内置效果都采用这种方式。

倒放会把文件里最响的部分从开头挪到结尾，因此还有两件事跟着变：

- 声音从文件末尾截取，而不是开头。否则最响的部分会被裁掉。
- `fadeDuration` 变成淡入而不是淡出。否则淡出正好压在最响的部分上。

倒放副本只生成一次并留在内存里。如果传入 `AudioBuffer`，会先复制——你的缓冲区不会被改动。

## 自定义播放器

```ts
const sound = ({ operation, element, signal }) => {
  const playback = audioEngine.play(operation === 'remove' ? 'card-out' : 'card-in');

  const stop = () => playback.stop();
  signal.addEventListener('abort', stop, { once: true });

  return {
    finished: playback.finished,
    stop,
    dispose() {
      signal.removeEventListener('abort', stop);
      playback.dispose();
    },
  };
};
```

播放器工厂会收到操作类型、目标元素与 `AbortSignal`。返回 `stop()` 处理取消，返回 `dispose()` 做无条件清理。

自动播放限制、请求、解码或自定义播放器错误会传递给 `onError`，但不会单独终止视觉动画和 DOM 操作。

## 错误隔离

自动播放限制、请求失败、解码错误以及自定义播放器抛出的异常，都不会仅因为声音而中断视觉操作。它们会转交给 `onError`，动画与所选的 DOM 操作照常继续。
