The default export is one class. It ties together capture, the animation, sound, the layout shift of the neighbours, background preparation, and storage for retained nodes.

The root and `/snapdom` entries preconfigure the four built-in effects and default to `dust`; only `/snapdom` also supplies a capture adapter. `/core` exposes the same lifecycle API without a default effect, particles, or built-in sounds. `/particles` contains factories and effect definitions rather than a `Disintegrator` class.

## Constructor

```ts
import Disintegrator from 'vanilla-disintegrate/snapdom';

const effects = new Disintegrator(options);
```

Important options:

| Option                 | Type                                                        | Default         | What it does                                                       |
| ---------------------- | ----------------------------------------------------------- | --------------- | ------------------------------------------------------------------ |
| `effect`               | `EffectSelection`                                           | `'dust'`¹       | Effect used when an operation does not pick one                    |
| `effects`              | `Record<string, EffectDefinition>`                          | `{}`            | Custom effects you can then select by name                         |
| `sound`                | `boolean \| SoundDefinition`                                | `false`         | `true` plays the phase sounds; a definition replaces them          |
| `layout`               | `boolean \| LayoutOptions`                                  | `true`          | Moves the neighbours into their new places after a removal         |
| `preparation`          | `boolean \| PreparationOptions`                             | `visible-idle`  | Prepares registered elements in the background                     |
| `audioPreparation`     | `false \| 'immediate' \| 'idle' \| AudioPreparationOptions` | `'immediate'`   | Prepares only enabled audio; `sound: false` still performs no work |
| `respectReducedMotion` | `boolean`                                                   | `true`          | Skips the animation when the user asked for less motion            |
| `capture`              | `SnapshotCapture`                                           | SnapDOM¹        | Turns an element into a canvas                                     |
| `overlayRoot`          | `HTMLElement \| () => HTMLElement`                          | `document.body` | Where the animation overlay is appended                            |
| `zIndex`               | `number`                                                    | `2147483646`    | Stack level of that overlay                                        |
| `random`               | `() => number`                                              | `Math.random`   | Seed source, called once per operation                             |
| `snapdom`              | `SnapdomOptions`                                            | —               | Passed to SnapDOM's `toCanvas()`. Only on the `/snapdom` entry     |
| `onTrigger`            | `(context) => void`                                         | —               | After validation, before capture starts                            |
| `onStart`              | `(context) => void`                                         | —               | After the DOM change, as playback begins                           |
| `onComplete`           | `(context) => void`                                         | —               | After a visual phase finishes normally                             |
| `onError`              | `(error, context) => void`                                  | —               | Capture, animation, sound and callback errors                      |

¹ The `dust` and SnapDOM defaults apply to `/snapdom`; the root entry supplies `dust` but no capture. `/core` supplies neither.

For operation failures, `context.operation` is `remove` or `restore`. Background snapshot preparation reports `prepare`, so it is never mislabeled as a content operation.

Pass a fixed `random` to make an effect reproducible: the same seed lays the particles out the same way every run, which is what makes a visual regression test possible.

## remove(target, options?)

Detaches the resolved element and returns `EffectOperation` synchronously.

```ts
const operation = effects.remove('.card', {
  effect: 'scatter',
  retain: true,
  sound: true,
  layout: { duration: 260 },
  detach: (element) => element.remove(),
});
```

`target` may be an `HTMLElement` or selector string. A missing selector throws before an operation starts.

`detach` replaces the default `element.remove()` commit. Use it when a reactive renderer must remove the node through its own state. If the callback throws, the error is sent to `onError` and native removal is used as a safe fallback.

## restore(target, options?)

Animates a connected, measurable element in its current geometry.

```ts
const operation = effects.restore(element, {
  effect: 'scatter',
  sound: true,
});
```

The method throws when the element is detached or has zero width or height.

## Retained elements

```ts
const element = effects.take(removalId); // HTMLElement | null
const discarded = effects.discard(removalId); // boolean
const count = effects.discardAll(); // number
```

`take()` consumes the stored entry. `discard()` and `discardAll()` release references without inserting content.

## Snapshot preparation

```ts
const unregister = effects.register(elements);
await effects.prepare(elements);
effects.invalidate(elements);
effects.clearPrepared();
```

`register()` follows the strategy you configured. `prepare()` captures right away, even when background preparation is off, and resolves with nothing once every element is done.

Repeated registrations of the same element are reference-counted; each returned unregister function releases only its own registration.

## Audio preparation

```ts
await effects.prepareAudio(['dust', 'wind']);
effects.discardPreparedAudio('dust');
effects.clearPreparedAudio();
```

With instance-level `sound: true`, the default effect is prepared automatically. Explicit methods still work while sound is disabled. Decoded buffers use a bounded LRU cache.

## destroy()

```ts
effects.destroy();
```

Cancels active operations, stops observers and background work, releases snapshot and decoded audio ownership, and clears retained nodes. The shared playback context closes when its last `Disintegrator` owner is destroyed. Calling `destroy()` more than once is safe; starting new work afterwards throws.

## EffectOperation

```ts
interface EffectOperation {
  readonly operation: 'remove' | 'restore';
  readonly removalId: RemovalId | null;
  readonly finished: Promise<{
    operation: 'remove' | 'restore';
    status: 'completed' | 'cancelled' | 'skipped' | 'rejected';
    removalId: RemovalId | null;
  }>;
  cancel(): void;
}
```

There is no `element` on the handle. The operation drops its reference as soon as it settles, so a handle you kept around cannot hold a detached node in memory.

| Status      | Meaning                                                                 |
| ----------- | ----------------------------------------------------------------------- |
| `completed` | The content action and visual phase both finished normally.             |
| `cancelled` | The content action committed, but visual or audio playback was stopped. |
| `skipped`   | The content action committed without a runnable visual phase.           |
| `rejected`  | The operation never started and did not change the DOM.                 |

## Callbacks and precedence

Instance callbacks run for every operation. Operation callbacks can be supplied alongside them. Operation options override instance defaults; a retained node's remembered effect is used by `restore()` only when the restore call has no explicit `effect`.
