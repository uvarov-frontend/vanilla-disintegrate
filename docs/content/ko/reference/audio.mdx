사운드는 기본으로 꺼져 있습니다. 내장 오디오를 쓰려면 `sound: true`를 전달하세요. 라이브러리가 Web Audio 재생을 재개할 수 있도록 클릭 같은 사용자 제스처에서 `remove()` 또는 `restore()`를 호출하세요. 각 삭제와 복원 단계는 독립된 사운드 정의를 가지므로 삭제 트랙을 역재생할 필요가 없습니다.

## 사운드 켜고 끄기

```ts
const audible = new Disintegrator({ sound: true });
const silent = new Disintegrator();
effects.remove(element, { sound: true });
```

작업 수준 값은 해당 호출에서만 인스턴스 설정을 덮어씁니다.

## 첫 상호작용 전에 준비하기

인스턴스에 `sound: true`를 설정하면 선택된 기본 효과를 즉시 가져와 디코딩합니다. 해당 효과만 준비하므로 `effect: 'vapor'`는 나머지 내장 파일 세 개를 불러오지 않습니다. 첫 렌더링이 첫 클릭 준비보다 중요하면 `idle`을 사용하세요.

```ts
const effects = new Disintegrator({
  effect: 'vapor',
  sound: true,
  audioPreparation: 'idle',
});
```

UI에서 여러 효과를 선택할 수 있다면 필요한 효과만 나열하거나 명시적으로 준비하세요.

```ts
const effects = new Disintegrator({
  sound: true,
  audioPreparation: {
    strategy: 'immediate',
    effects: ['dust', 'scatter', 'vapor', 'wind'],
  },
});

await effects.prepareAudio(['dust', 'wind']);
effects.discardPreparedAudio('dust');
effects.clearPreparedAudio();
```

`audioPreparation: false`는 자동 준비를 끕니다. `prepareAudio()`는 명시적 호출이므로 인스턴스 사운드가 꺼져 있어도 동작합니다. 작업이 준비되지 않은 네이티브 사운드를 선택하면 시각 효과와 오디오가 디코딩을 기다린 뒤 함께 시작하며, 내장 사운드가 실행 중인 애니메이션에 늦게 합류하지 않습니다. 사용자 플레이어 팩토리는 자체 로딩을 관리하며 준비 단계에서 호출되지 않습니다.

정방향 및 역방향 디코딩 버퍼는 기본 8 MiB LRU 예산을 공유합니다. `audioPreparation.cacheByteBudget`으로 조절할 수 있고, `destroy()`는 전체 캐시를 비우고 재생 컨텍스트를 닫습니다.

## 사운드를 어디에 두나

사운드는 효과 안에 단계별로 하나씩 둡니다.

```ts
const snap = '/sounds/snap.mp3';

const fold = defineEffect({
  remove: { animate: out, sound: { src: snap } },
  restore: { animate: back, sound: { src: snap, reverse: true } },
});
```

인스턴스나 호출의 `sound`는 그 사운드의 켜고 끄는 스위치입니다.

```ts
const effects = new Disintegrator({ effect: fold, sound: true });

effects.remove(card); // 효과에 정의된 사운드를 재생
effects.remove(card, { sound: false }); // 무음, 애니메이션은 그대로
```

한 가지 주의점이 있습니다. 거기에 `true`나 `false` 대신 사운드를 넘기면 스위치로 동작하지 않습니다. 효과의 사운드를 대체하고 두 단계가 같은 파일을 씁니다.

```ts
new Disintegrator({ sound: { src: '/sounds/snap.mp3' } });
// 삭제와 복원 모두 snap.mp3를 정방향으로 재생
```

사운드가 하나면 편한 방식입니다. 삭제와 복원에 서로 다른 사운드를 주려면 효과 안에 적으세요.

## 삭제와 복원 짝짓기

| 원하는 것                 | `remove`        | `restore`                      |
| ------------------------- | --------------- | ------------------------------ |
| 파일 하나, 복원 때 거꾸로 | `{ src: snap }` | `{ src: snap, reverse: true }` |
| 서로 다른 파일 둘         | `{ src: out }`  | `{ src: back }`                |
| 삭제할 때만 소리          | `{ src: snap }` | `null`                         |

네 가지 내장 효과 모두 첫 번째 행을 사용합니다.

## 지원 소스

```ts
type SoundSource = string | URL | ArrayBuffer | AudioBuffer;
```

문자열과 `URL`은 자동, 명시적 또는 온디맨드 준비 과정에서 fetch 및 decode됩니다. 자체 리소스 로더가 있으면 `ArrayBuffer`, 이미 오디오 자산 파이프라인을 운영한다면 재사용 가능한 `AudioBuffer`를 전달할 수 있습니다.

라이브러리는 압축 파일을 소스 코드의 `AudioBuffer`로 강제 변환하지 않습니다. 디코딩은 브라우저 런타임 작업이고 압축 파일이 더 작고 캐시하기 좋기 때문입니다.

## 재생 옵션

```ts
effects.remove(element, {
  sound: {
    src: new URL('/sounds/snap.ogg', location.href),
    gain: 0.35,
    delay: 40,
    duration: 0.7,
    fadeDuration: 0.12,
    playbackRate: 1.05,
  },
});
```

## 거꾸로 재생하기

복원 애니메이션은 독립적이지만, 사운드는 삭제 녹음을 거꾸로 재생할 수 있습니다. 그러면 파일 하나로 두 단계를 모두 쓸 수 있고 두 번째 녹음은 필요 없습니다.

```ts
const remove = { src: '/sounds/snap.mp3' };
const restore = { src: '/sounds/snap.mp3', reverse: true };
```

네 가지 내장 효과 모두 이 방식을 사용합니다.

거꾸로 재생하면 파일에서 가장 큰 소리가 앞에서 뒤로 옮겨갑니다. 그래서 두 가지가 함께 바뀝니다.

- 소리를 파일의 앞이 아니라 뒤에서 잘라 씁니다. 그러지 않으면 큰 소리 부분이 잘려나갑니다.
- `fadeDuration`이 페이드아웃이 아니라 페이드인이 됩니다. 그러지 않으면 페이드가 큰 소리 부분에 걸립니다.

뒤집은 사본은 한 번만 만들어 메모리에 둡니다. `AudioBuffer`를 넘기면 복사해서 쓰므로 원본 버퍼는 그대로입니다.

## 사용자 플레이어

팩토리는 작업 종류, 대상 요소, `AbortSignal`을 받습니다. 취소를 위한 `stop()`과 항상 실행되는 정리를 위한 `dispose()`를 반환할 수 있습니다.

자동 재생 제한, fetch, decode, 사용자 플레이어 오류는 `onError`로 전달되지만 시각 애니메이션과 DOM 작업을 중단하지 않습니다.

## 오류 격리

자동 재생 제한, 요청 실패, 디코딩 오류, 커스텀 플레이어의 예외는 오디오 때문에 시각적 작업을 취소하지 않습니다. 모두 `onError`로 전달되며 애니메이션과 선택된 DOM 동작은 계속됩니다.
