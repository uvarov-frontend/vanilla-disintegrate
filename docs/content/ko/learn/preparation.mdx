요소를 캡처하는 데는 크기와 폰트, 이미지에 따라 몇 밀리초에서 수백 밀리초가 걸립니다. 준비는 그 작업을 미리 해 두어 `remove()`가 곧바로 그리기 시작하게 합니다.

기본 정책은 `visible-idle`입니다. 라이브러리가 DOM을 직접 탐색하지는 않습니다. 후보 요소를 `register()`에 전달한 뒤에만 옵저버와 백그라운드 작업이 시작됩니다. `preparation: false`로 이 작업을 완전히 끌 수 있습니다.

## 후보 요소 등록하기

```ts
const effects = new Disintegrator();

const unregister = effects.register(document.querySelectorAll('[data-effects]'));
```

기본값과 명시적인 `preparation: true` 모두 `visible-idle`을 선택합니다. 등록된 요소가 뷰포트에 가까워지고 브라우저가 idle일 때 준비합니다.

더 이상 준비할 필요가 없으면 `unregister()`를 호출하세요. 등록은 참조 횟수를 셉니다. 두 컴포넌트가 같은 노드를 등록했다면 각 해제 함수는 자신의 등록만 해제하며 둘 다 해제된 뒤에 관찰을 멈춥니다.

## 실행 조건 설정

```ts
const effects = new Disintegrator({
  preparation: {
    strategy: 'visible-idle',
    rootMargin: '300px 0px',
    concurrency: 1,
    shouldPrepare: (element) => element.matches('[data-effects]'),
    invalidateOnResize: true,
    observeMutations: false,
    cachePixelBudget: 8_000_000,
  },
});
```

| 전략           | 동작                                             |
| -------------- | ------------------------------------------------ |
| `immediate`    | 동시성 여유가 생기면 즉시 캡처합니다.            |
| `idle`         | timeout 대체 수단과 함께 idle 구간을 기다립니다. |
| `visible-idle` | 뷰포트 근접을 확인한 후 idle을 기다립니다.       |

`shouldPrepare(element)`는 작업 예약 전에 실행되므로 요소 유형, UI 상태, 네트워크, feature flag를 반영할 수 있습니다.

## 캐시 직접 제어

```ts
await effects.prepare(elements); // 지금 캡처
effects.invalidate(elements); // 오래된 항목 제거 및 재예약
effects.clearPrepared(); // 전체 캐시 해제
```

작업은 확신할 수 없는 스냅샷으로 애니메이션하지 않습니다. 스냅샷이 없거나, 아직 만들어지는 중이거나, 오래됐거나, 캐시에서 밀려났다면 먼저 새로 캡처합니다.

캐시는 기본으로 800만 물리 픽셀까지 담고, 넘치면 가장 오래 쓰이지 않은 스냅샷을 버립니다. 세는 대상은 스냅샷뿐이고 보관된 DOM 노드는 포함되지 않습니다. 버려진 스냅샷은 캔버스 크기를 0으로 만들어 브라우저가 메모리를 되찾게 합니다.

`invalidateOnResize`는 기본으로 켜지고 MutationObserver는 비용 때문에 기본으로 꺼져 있습니다. 콘텐츠 모양이 바뀌면 `invalidate()`를 호출하세요.
