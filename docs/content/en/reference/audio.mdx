Sound is opt-in: pass `sound: true` to use the built-in audio. Call `remove()` or `restore()` from a user gesture such as a click so the library can resume Web Audio playback. Each remove and restore phase owns an independent sound definition, so matching visuals do not have to share or reverse one audio track.

## Enable and disable sound

```ts
const audible = new Disintegrator({ sound: true });
const silent = new Disintegrator();

effects.remove(element, { sound: true });
```

An operation-level value overrides the instance for that one call.

## Prepare before the first interaction

With instance-level `sound: true`, the selected default effect is fetched and decoded immediately. Only that effect is prepared: `effect: 'vapor'` does not load the other three built-in files. Use `idle` when initial rendering matters more than first-interaction readiness:

```ts
const effects = new Disintegrator({
  effect: 'vapor',
  sound: true,
  audioPreparation: 'idle',
});
```

If the UI can choose several effects, list exactly those effects or prepare them explicitly:

```ts
const effects = new Disintegrator({
  sound: true,
  audioPreparation: {
    strategy: 'immediate',
    effects: ['dust', 'scatter', 'vapor', 'wind'],
  },
});

await effects.prepareAudio(['dust', 'wind']);
effects.discardPreparedAudio('dust');
effects.clearPreparedAudio();
```

`audioPreparation: false` disables automatic work. `prepareAudio()` remains explicit and therefore works even while instance sound is off. If an operation selects an unprepared native sound, the visual and audio wait for decoding and then start together; audio never joins a running built-in animation late. Custom player factories own their loading and are not invoked by preparation.

Each instance owns an 8 MiB LRU budget for decoded forward and reversed buffers by default. Instances on the same page reuse one fetch, decoded buffer, and `AudioContext`; a shared buffer counts toward every instance that prepared it but occupies memory only once. Configure the per-instance budget with `audioPreparation.cacheByteBudget`. Eviction or `destroy()` releases only that instance's buffer ownership. The buffer is deleted after its final owner releases it; the shared context closes when the final live instance is destroyed.

## Where to put the sound

The sounds live in the effect, one per phase:

```ts
const snap = '/sounds/snap.mp3';

const fold = defineEffect({
  remove: { animate: out, sound: { src: snap } },
  restore: { animate: back, sound: { src: snap, reverse: true } },
});
```

The `sound` option on the instance or on a call is an on/off switch for them:

```ts
const effects = new Disintegrator({ effect: fold, sound: true });

effects.remove(card); // plays the sound from the effect
effects.remove(card, { sound: false }); // no sound, same animation
```

One catch. If you pass a sound there instead of `true` or `false`, it does not switch anything — it replaces the sounds in the effect, and both phases get the same file:

```ts
new Disintegrator({ sound: { src: '/sounds/snap.mp3' } });
// remove and restore both play snap.mp3 forwards
```

That is handy when one sound covers everything. To give remove and restore different sounds, put them in the effect.

## Pairing remove and restore

| What you want                         | `remove`        | `restore`                      |
| ------------------------------------- | --------------- | ------------------------------ |
| One file, played backwards on restore | `{ src: snap }` | `{ src: snap, reverse: true }` |
| Two different files                   | `{ src: out }`  | `{ src: back }`                |
| Sound only when removing              | `{ src: snap }` | `null`                         |

All four built-in effects use the first row.

## Supported sources

```ts
type SoundSource = string | URL | ArrayBuffer | AudioBuffer;
```

Strings and `URL` values are fetched and decoded during automatic, explicit, or on-demand preparation. `ArrayBuffer` is useful when the application already controls loading. `AudioBuffer` is the most direct reusable form when the application owns an `AudioContext`-based asset pipeline.

The library does not force bundled audio into source code as `AudioBuffer`: browser decoding is runtime work, and encoded files remain smaller and cacheable. Internally decoded results can still be reused.

## Playback options

```ts
const sound = {
  src: new URL('/sounds/snap.ogg', location.href),
  gain: 0.35,
  delay: 40,
  duration: 0.7,
  fadeDuration: 0.12,
  playbackRate: 1.05,
};

effects.remove(element, { sound });
```

## Playing a sound backwards

The restore animation is independent, but its sound can be the removal recording played backwards. One file then covers both phases; no second recording:

```ts
const remove = { src: '/sounds/snap.mp3' };
const restore = { src: '/sounds/snap.mp3', reverse: true };
```

That is how all four built-in effects work.

Reversing moves the loud part of the file from the start to the end, so two more things change with it:

- The sound is cut from the end of the file, not the start. Otherwise the loud part would be trimmed off.
- `fadeDuration` fades in instead of out. Otherwise the fade would land on the loud part.

The reversed copy is made once and kept in memory. If you pass an `AudioBuffer`, it is copied — your buffer is left alone.

## Custom player

Use a factory to integrate an existing audio engine.

```ts
const sound = ({ operation, element, signal }) => {
  const playback = audioEngine.play(operation === 'remove' ? 'card-out' : 'card-in');

  const stop = () => playback.stop();
  signal.addEventListener('abort', stop, { once: true });

  return {
    finished: playback.finished,
    stop,
    dispose() {
      signal.removeEventListener('abort', stop);
      playback.dispose();
    },
  };
};
```

The factory receives the operation, target element, and abort signal. Return `stop()` for cancellation and `dispose()` for unconditional cleanup.

## Failure isolation

Autoplay restrictions, fetch failures, decode errors, and custom player exceptions never reject the visual operation solely because of audio. They are forwarded to `onError`; animation and the selected DOM action continue.
