A custom effect is two animations: one for removing an element, one for putting it back. You write the animation and pick the sound. The library captures the element, measures it, and takes care of cancelling and cleaning up.

## Configure particles with the playground

The playground on the home page generates a complete custom effect with independent particle and sound settings for removal and restoration. For example, this output combines `scatter` removal with `vapor` restoration:

```ts
import Disintegrator, { createParticleEffect, particlePresets } from 'vanilla-disintegrate/snapdom';

const sharedSoundOptions = {
  volume: 0.32,
  playbackRate: 1,
  delay: 0,
  fadeDuration: 0.18,
};

export const disintegrator = new Disintegrator({
  effect: createParticleEffect({
    remove: particlePresets.scatter,
    restore: particlePresets.vapor,
  }),
  sound: {
    remove: {
      ...sharedSoundOptions,
      src: 'scatter',
      reverse: false,
    },
    restore: {
      ...sharedSoundOptions,
      src: 'vapor',
      reverse: true,
    },
  },
});
```

`createParticleEffect()` uses the built-in particle renderer. Configure both phases in the playground, copy the generated code, and use it without writing a Canvas or WebGL renderer. The next section is only needed when you want to implement the rendering itself.

See the [Particle API](/docs/reference/particles/) for every motion option, its default, accepted range, and the low-level phase factories.

## Control particle render quality

`renderQuality` controls the resolution of the built-in WebGL renderer, independently from the capture adapter. The default `auto` mode protects memory and GPU work by limiting the renderer's source texture to 2,000,000 pixels and 2,048 pixels per side, and its expanded animation surface to 4,000,000 pixels.

Use `exact` when preserving the capture's full resolution is more important than those software limits:

```ts
const exactEffect = createParticleEffect({
  remove: { ...particlePresets.vapor, renderQuality: 'exact' },
  restore: { ...particlePresets.scatter, renderQuality: 'exact' },
});
```

Or set an explicit budget:

```ts
const boundedEffect = createParticleEffect({
  remove: {
    ...particlePresets.vapor,
    renderQuality: {
      maxSourcePixels: 4_000_000,
      maxSourceDimension: 4096,
      maxRenderPixels: 8_000_000,
    },
  },
});
```

`exact` disables software downscaling, but it cannot bypass the device's WebGL texture and viewport limits. An unsupported exact surface is reported through `onError` instead of being silently degraded. Prefer `auto` for unknown or large elements; full resolution grows roughly with the square of the device pixel ratio.

## Raise or lower the WebGL context ceiling

```ts
import { configureParticleContexts } from 'vanilla-disintegrate/snapdom';

configureParticleContexts({ maxContexts: 2, maxIdleContexts: 1 });
```

The particle renderer keeps at most 4 WebGL2 contexts alive at once across the whole page, with up to 2 kept warm for reuse after an effect finishes. This ceiling is page-wide rather than per-effect: browsers already cap how many live contexts a page may hold, and asking two effects for different values would leave no single correct answer.

An effect that cannot acquire a context because the page has reached the ceiling follows the same path as a browser with no WebGL2 at all: `remove()` still detaches the element and `restore()` still reveals it. A configured `fallback` runs instead; without one, the operation resolves with status `skipped` and `onError` receives a generic "did not create an animation" error rather than one naming contention as the cause. Call `configureParticleContexts()` once, before any effect runs, to change the ceiling for the rest of the page's lifetime. Lower it on memory-constrained devices; raise it only up to what the browser itself allows, since exceeding that just moves where contexts get discarded.

## A fallback without WebGL2

For a phase with `requires: 'webgl2'`, pass a matching `remove`/`restore` pair as the constructor's `fallback`. It may use CSS, the Web Animations API, Canvas 2D, SVG, or a custom renderer, but not WebGL2. It runs when WebGL2 is unavailable or the built-in particle renderer cannot start; with unavailable WebGL2, the library selects it **before capture**. It runs without built-in sound. See the full contract and example in the [API](/docs/reference/api/#webgl2-fallback).

## Use the snapshotless core

When both phases set `needsSnapshot: false`, import `/core`: no capture adapter, particle renderer, or built-in audio enters the module graph.

```ts
import Disintegrator, { defineEffect } from 'vanilla-disintegrate/core';

const fade = defineEffect({
  remove: {
    needsSnapshot: false,
    animate: ({ element, layer }) => {
      const visual = element.cloneNode(true) as HTMLElement;
      Object.assign(visual.style, {
        height: '100%',
        inset: '0',
        margin: '0',
        pointerEvents: 'none',
        position: 'absolute',
        width: '100%',
      });
      layer.append(visual);
      return visual.animate([{ opacity: 1 }, { opacity: 0 }], { duration: 240 });
    },
  },
  restore: {
    needsSnapshot: false,
    animate: ({ element, layer }) => {
      const visual = element.cloneNode(true) as HTMLElement;
      Object.assign(visual.style, {
        height: '100%',
        inset: '0',
        margin: '0',
        pointerEvents: 'none',
        position: 'absolute',
        width: '100%',
      });
      layer.append(visual);
      return visual.animate([{ opacity: 0 }, { opacity: 1 }], { duration: 240 });
    },
  },
});

const effects = new Disintegrator({ effect: fade });
```

## Animation context

The factory receives:

- `operation` — `remove` or `restore`
- `element` — the element itself
- `bounds` — where it sits on screen, as a `DOMRectReadOnly`
- `layer` — an empty overlay already positioned over those bounds
- `snapshot` — the captured canvas, or `null`
- `visual` — a full-size canvas with the snapshot drawn on it, created on first use
- `signal` — aborts when the operation is cancelled or the instance is destroyed
- `random()` — random numbers for this operation, seeded so a run can be reproduced
- `reducedMotion` — always `false` while a factory runs; reduced-motion requests skip before it is called
- `addCleanup(fn)` — whatever you register here runs however the operation ends

On restore, `bounds` is the **new** place where you inserted the element, not where it was removed from.

## Supported results

An animation factory may return:

```ts
type AnimationResult =
  | Animation
  | PromiseLike<unknown>
  | {
      element?: HTMLElement;
      finished: PromiseLike<unknown>;
      duration?: number;
      layoutDelay?: number;
      cancel?(): void;
      dispose?(): void;
    }
  | null;
```

So a Web Animation, a promise, a Canvas or WebGL loop, or a wrapper around another engine all fit. `cancel()` stops playback. `dispose()` frees whatever your renderer allocated, and it runs whether the animation finished, was cancelled, or failed.

## Create your own preset

A custom `effect` is silent by default. When animation and audio should travel together as one reusable choice, wrap them in a complete preset:

```ts
import { definePreset } from 'vanilla-disintegrate';

const vortex = definePreset({
  effect: particleVortex,
  sound: {
    remove: { src: 'vapor', volume: 0.35 },
    restore: { src: 'vapor', volume: 0.35, reverse: true },
  },
});

const effects = new Disintegrator({
  preset: 'vortex',
  presets: { vortex },
});

effects.remove(element);
```

The built-in preset names are registered by the root and `/snapdom` entries. `/core` only sees presets supplied through `presets` or passed inline through `preset`.

## Add custom audio

Keep audio separate from visual phases. The constructor accepts independent `remove` and `restore` definitions; omit `sound` when the custom effect should be silent.

```ts
const effects = new Disintegrator({
  effect: particleVortex,
  sound: {
    remove: { src: '/sounds/remove.ogg', volume: 0.35 },
    restore: ({ signal }) => startMyAudioEngine(signal),
  },
});
```

`src` also accepts a bundled name, `URL`, local `Blob`/`File`, `ArrayBuffer`, typed-array view, or `AudioBuffer`. If audio fails, the error goes to `onError` and the animation and DOM change continue.
